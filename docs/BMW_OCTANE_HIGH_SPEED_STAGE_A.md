# BMW OCTANE 2.0 — High-Speed Engine, Stage A / experimental request budgeting

Основа: экспериментальная BMW OCTANE 2.0.1 (build 203, PR #24) с исправленной первой заправкой PR #23/#25. Эта ветка оставляет `main` неизменной и сохраняет старые CSV.

## Состояние

**Только инструментально проверяемый этап A + ограниченный этап планировщика.** Новая APK имеет `versionName=2.0.1-experimental`, `versionCode=204`. **20–50 Гц НЕ измерены и НЕ гарантированы.**

1. `HighSpeedMetrics`: число запросов, успешных ответов, ошибок и изменений байтов ответа по каждому OBD PID, DID и пакету; Android monotonic latency для формирования, отправки, первого байта, получения оставшейся части HSFZ, декодирования. Ограниченное окно 128 замеров, nearest-rank median/p95/p99/max. Равные байты — лишь равный ответ, не доказательство stale в DME.
2. `FirstByteMeasuredStream`: наблюдение времени первого прочитанного байта без чтения дополнительных байтов, без второго TCP reader. Декодирование остаётся строго на прежних проверенных `HsfzCodec`, `DiagnosticResponse`, `MixedDidBatch`, `DmeBatchParser`. Отсутствующий/повреждённый ответ не становится успешным.
3. `AsyncCsvWriter`: доступен счётчик ожидания, запись, потери после ошибки записи, глубина очереди, p95 ожидания и записи. Бounded `Channel` сохраняет порядок и backpressure. Некоторые неосновные журналы остаются синхронными — это не гарантия полностью неблокирующего FAST-цикла.
4. Дополнительный CSV `bmw_highspeed_benchmark_v1_<trip_id>.csv`, без изменения существующих схем. Данные включают trip ID, fuel session ID, connection epoch, профиль, poll mode, request/success/error, byte changes, latency, глубину/потери CSV и число валидных цилиндровых knock/ignition. Экспорт раз в 5 с. Значения Android timestamp — **не timestamps внутреннего измерения ECU**.
5. `HighSpeedProfilePolicy`: `LEGACY` (по умолчанию, прежние до двух SLOW/FAST), `HIGH_SPEED_CORE` (не более одного SLOW/FAST, при долгом FAST цикле можно пропустить SLOW), `HIGH_SPEED_EXTENDED` (прежние два SLOW/FAST). Меняет **только** бюджет уже существующих необязательных SLOW транзакций на одном TCP сокете; не вводит неизвестные RAM DID и не меняет список FAST. При ошибках/нестабильностиCORE/EXTENDED может временно пропустить SLOW. Переключение происходит строго между FAST-циклами и разрывает частичный измерительный сегмент.
6. В разделе «Диагностика»: ненавязчивый High-Speed status раз в 5 с, кнопка экспериментальных профилей, offline отчёт о структуре CSV. UI не обновляется 50 раз/с ради показателей.
7. Прежний `RefuelSessionStore` сохраняет первую сессию №1, pending/refuel/mixing границы и исправление марки без удаления диагностических CSV. Вещание статистики не меняет Fuel Score.

## Что НЕ входит и не должно выдаваться за готовое

- Измерения производительности реального автомобиля с VXSCAN/ENET — требуют дорожной проверки; никакого достижения 20–50 Гц не заявляется.
- Нельзя восстановить точный внутренний ECU timestamp или достоверную частоту собственных обновлений DME по одинаковым значениям.
- RAM 0x23 использует переиспользуемый HSFZ buffer из PR #24, но RAM-этап ещё не включён в новую универсальную статистику транзакций.
- Отдельные старые журналы, сравнение и часть FAST-анализа могут записываться синхронно; общий zero-allocation парсинг не реализован.
- Профилированные задержки помогают находить узкие места, но не заменяют приборное измерение тока/нагрузки DME.
- Прямые `0x22` для новых неизвестных сигналов, скан RAM, ECU write, coding, reset запрещены.
- `LEGACY` не отключает безопасный CPU overhead профилирования; реальные накладные расходы измерить на устройстве.
- Не реализован A/B hardware benchmark или нагрузочная симуляция DME со всеми задержками. Не выполнена инструментальная Android UI/lifecycle проверка.

## План автомобильной проверки

1. На стоящем автомобиле выбрать подтверждённое топливо и подсоединить VXSCAN/ENET. `LEGACY` 5–10 минут: контроль полного knock/ignition, ошибок, потерь CSV, профили p95/p99, фоновые медленные поля.
2. Результат сравнить в `HIGH_SPEED_CORE` при тех же условиях и без опасных манёвров. Если нет выигрыша или устаревают SLOW/скорость, немедленно вернуть `LEGACY`.
3. Повторить безопасный обычный заезд при сопоставимых режимах RPM/MAP, отдельно сравнить `HIGH_SPEED_EXTENDED`.
4. Проверить STOP/reconnect/отмену, ручную и автоматическую заправку, переход `MIXING`, сохранение CSV до и после смены сессии.
5. Только после объективного A/B и статистики доработать batching, RAM и low-allocation для широкой FAST-матрицы.

Откат: в настройках вернуть `LEGACY`; для полного отката — установить предыдущий проверенный экспериментальный APK 203, сохранив копии пользовательских данных. PR не объединять до испытаний автомобиля.
