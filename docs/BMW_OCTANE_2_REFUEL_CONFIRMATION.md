# BMW OCTANE 2.0.1 LAB — подтверждение новой заправки

**Рабочая ветка:** `feature/octane2-refuel-confirmation`, PR #23 (base `experiment/bmw-octane-2.0`). `main` и основная установленная 1.7 не затронуты. Отдельный пакет `com.example.bmwenettest.octane2`.

## Зачем исправлено

Предыдущий `EnetLoggerService` автоматически увеличивал `fuel_session_id` после обнаружения OBD 0x2F, до подтверждения пользователя. Ложное событие не могло вернуть правильную логическую сессию. Теперь **физическое предположение**, **подтверждение пользователя** и **диагностическая сессия** разделены.

## События и состояние

- `FuelRefillDetector` без изменения порогов: стандартный read-only OBD `01 2F`, значительный подъём минимум на 12 процентных пунктов, минимум три согласованных чтения за >=20 с. Кратковременный скачок, неверный или неподдерживаемый PID не создают подтверждённую заправку. Небольшие доливы могут быть пропущены — есть ручной сценарий.
- `RefuelSessionStore.detected` сохраняет **REFUEL_PENDING** с временем, начальным/конечным % топлива, устойчивым уникальным ID события и прежней сессией в SharedPreferences через `commit()`. Не меняет `fuel_session_id`; останавливает допуск точек в Fuel Score и тест топлива, не прерывает транспорт и не удаляет CSV. Повторное обнаружение возвращает тот же ID.
- Главная вкладка показывает ненавязчивый баннер. Автоматический диалог — только при работающем DME и не менее 15 секунд свежих показаний 0 км/ч; если автомобиль движется или скорость неизвестна, диалог не появляется. Подтвердить вручную можно после остановки.
- **Подтвердить и начать анализ:** одна атомарная операция для ручного/автоматического сценария: новая логическая сессия (`fuel_session_id+1`), стабильный `GuidedFuelTest.PREF_ID` без привязки к марке бензина, метаданные, включение теста, переход `MIXING`, сброс нового прогресса. Сервис видит смену ID в своём цикле, меняет лог-файл и счётчики **без реконнекта и второго TCP reader**.
- **Заправки не было:** pending удаляется, прежний ID/CSV остаются, прежняя активность теста восстанавливается; сомнительные RAW-сигналы периода события остаются в журнале.
- **Позже:** не меняет prefs, событие сохраняется после гибели процесса, перезапуска LOGGER, смены Activity. Если подключение неактивно, на главной остаётся баннер и можно подтвердить сознательным действием.
- **Изменить топливо:** текущая или архивная заправка; обновляется только `grade/station/rating`. Исходный ID, `fuel_session_id`, замеры, CSV и прогресс не меняются. Новая оценка 2.0 по-прежнему остаётся неподтверждённой.
- Новый append-only `bmw_refuel_decisions_v2.csv` регистрирует `PENDING / CONFIRMED / REJECTED / METADATA_EDIT` без удаления старого `bmw_fuel_events.csv`. Исторические файлы версии 1.7 остаются доступными, старый журнал — только для чтения.

## Защита границ данных

Детектор лишь информирует. Уже **кандидатный рост** уровня (до окончательной стабилизации), подтверждённый `REFUEL_PENDING`, ожидающая смена SharedPreferences сессии и `MIXING` исключают диагностические точки из сравнения топлива и принятых STEADY-участков; сырые FAST данные пишутся. Границы события сохраняются отдельными строками `REFUEL_PENDING` / `REFUEL_CONFIRMED` в журнале наблюдений и временными метками в event-CSV. Данные, собранные **до подтверждения** и во время смешивания, хранятся, но **не переносятся ретроактивно в принятые точки нового топлива**: невозможно достоверно определить состав смеси. После подтверждения следующий завершённый цикл записывается под новым session ID.

Унаследованная дистанция **5 км** — исключительно эвристический минимум исключения, а **не научное доказательство полного перемешивания**. Отсчёт допускается только при свежем OBD-показании скорости и после подтверждения. Реальная степень смешивания и доверие к модели требуют измерения/валидации; результат 2.0 не является лабораторным RON.

## Совместимость и тесты

Никаких изменений RAM LAB, socket, HSFZ/UDS/OBD packet parser, диалогов A2L/SWFL и источников детонации. `RefuelSessionStore` принимает тестовые SharedPreferences для автоматизированных JVM тестов. Сценарии: устойчивый и кратковременный подъём; восстановление pending из нового экземпляра; подтверждение/повторное подтверждение; отказ и восстановление прежней сессии; метаданные (включая старый CSV), ручной/автоматический дедуп; отсутствие пригодных точек во время MIXING.

Сборка `:app:testDebugUnitTest`, `:app:lintDebug`, `:app:assembleDebug` — GitHub Actions PR #23. Дорожные испытания ENET/VXSCAN, PID 2F, поведения датчика на уклоне, подвешенных соединений и реального смешивания не заменяются успешной сборкой.

**Откат:** PR остаётся отдельным, main неизменен. Старая экспериментальная версия может быть собрана из коммита `59d25e15ef7e`; в новом APK прежние CSV не мигрируются/не переписываются.
