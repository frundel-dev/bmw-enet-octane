# BMW OCTANE 2.0 — FAST DID / Knock Semantics Audit

## Версия, границы и исходная точка

Ветка `experiment/octane2-fast-did-semantics-audit` основана на последнем HEAD Stage A PR #27 (`ef8b7682c0120979cf0c972d77041cafb1187380`). В данной итерации **запросы к новым DID не выполняются**, `main` не меняется. Предыдущее поведение B+, OBD, RAM, рефилла и Fuel Score не пересчитывается. Новый отчёт является **офлайн-аудитом + пассивной instrumented регистрацией**, не доказательством DME-семантики.

### Доказательная база

1. **ПРОВЕРЕНО в исходниках GitHub:** `MixedDidBatch.kt` запрашивает knock DID `0x4A37…0x4A3A` как четыре байта каждый и ignition как два байта, проверяет порядок и полную длину; `EnetLoggerService.kt` применяет `raw * 0.05 / 65536` к первым четырём байтам. Результат исторически называется `knock_z1_vms` … `knock_z4_vms`. `DmeReadOnlyProbe.kt` уже содержит `0x4A36` и `0x554A`, называет 0x554A кандидатом адаптации, а не мгновенной коррекции.
2. **Сообщено в задании, независимо не подтверждено:** `bootmod3 3.3.1 mock_channels.json` содержит демонстрационные DID `0x5819`, `0x5804`, `0x4A2D` и возможное двухбайтное представление «Normalized Ref Level». Это НЕ карта нашего DME.
3. **НЕ ДОСТУПНО / НЕ ПРОВЕРЕНО:** исходный бинарный PRG/A2L с обоснованным mapping каждого DID на SWFL `00005D55-070.060.007` и RAW-положительные ответы именно этого ECU. Настройки приложения `octane2_swfl_confirmed` являются лишь подтверждением пользователя, **не документальной аттестацией A2L**. Без SWFL-специфичной документации нельзя приписывать физические единицы.

## Таблица источников

| DID | Предварительное назначение | Формат по доступным данным | Статус | Допуск новых запросов |
| --- | --- | --- | --- | --- |
| `5819` | Engine Speed | mock u16 BE × 0.5 RPM | NOT_VERIFIED | НЕТ |
| `5804` | Load Actual Relative | mock u8 × 0.390625% | NOT_VERIFIED | НЕТ |
| `4A2D` | Manifold Absolute Pressure | mock u16 BE × 0.078125 hPa (÷10 → kPa) | NOT_VERIFIED | НЕТ |
| `4A37–4A3A` | Текущие четыре knock канала | рабочий парсер **u32 BE** × 0.05/65536; смысл НЕ подтверждён | NOT_VERIFIED, SEMANTICS_UNVERIFIED | Никаких дополнительных запросов; существующий B+ без изменений |
| `4A36` | Текущий статус детонации | рабочий путь читает первый байт; словарь состояний не подтверждён | NOT_VERIFIED | Используется только существующий запрос |
| `5883,5885,5886,5888` | Knock Control Reference (кандидаты) | неизвестно | NOT_VERIFIED | НЕТ |
| `554A` | Адаптация детонационного регулирования (кандидат) | старый диагностический модуль содержит предположительный signed16 × 0.1° | NOT_VERIFIED | Никаких дополнительных запросов этой итерации |

Результат `SEMANTICS_UNVERIFIED` принципиален: «Normalized Ref Level knock control» может быть опорным/нормализованным уровнем, а не непосредственной интенсивностью детонации, и на данный момент это **гипотеза**, не доказательство ошибки имеющегося коэффициента. Демонстрационный 2-байтный формат **НЕ применяется** к реальным 4-байтным измерениям, старые CSV и Fuel Score не исправляются скрыто.

## Реализованный программный аудит

- `FastDidValidation.kt`: версии статусов `NOT_VERIFIED`, `DOCUMENTED`, `RAW_CONFIRMED`, `SEMANTICS_VALIDATED`, `REJECTED`; строгий offline UDS `0x62` mixed-width decoder, NRC/порядок/длина; **демонстрационный preview**, который не используется в реальном FAST; неизменяемый пустой список `documentedForTargetSwfl` запрещает новые UDS-запросы при любом параметре пользователя.
- Экспериментальные профили `BASELINE`, `FAST_DID_TEST`, `FAST_BATCH_TEST`. **Только BASELINE доступен**, другие явно BLOCKED до документального/автомобильного подтверждения и отдельной ревизии разрешённого набора.
- `bmw_fast_did_validation_v1_<trip_id>.csv`: при запуске сохраняет `NO_ADDITIONAL_QUERY` для неподтверждённых кандидатов с пустым RAW (**НЕ нулём**). `FastDidPassiveRecorder` получает уже декодированные результаты OBD/UDS непосредственно после проверенного сопоставления ответа и запроса в существующем владельце TCP, **не создаёт новых ECU-запросов**. Для `0x4A36/0x4A37–0x4A3A` каждые ≥5 секунд **по каждому DID** сохраняет сырые байты поля, Android monotonic start/end транзакции, актуальные контрольные OBD RPM/LOAD/MAP, их возраст, trip/fuel/epoch (epoch отслеживается по смене TCP-сокета) и старый коэффициент с `SEMANTICS_UNVERIFIED`. Это **не полный HSFZ/UDS конверт**, а RAW-полезные байты уже принятого поля, и не ECU timestamp. Исследовательские строки поступают в ограниченную `AsyncCsvWriter.offerAudit` без блокировки FAST; переполнение фиксируется как потеря и ошибка, **не маскируется**. Основной CSV продолжает использовать исходный suspending backpressure.
- На экране «Диагностика» добавлена компактная панель FAST DID Validation со статусами и просмотром offline RAW CSV. Никаких новых запросов к ECU или вывода демонстрационных значений на главный экран.
- Важное ограничение: текущая итерация ещё **не** оснащена подтверждением нового реального SWFL/DID, активным parked-only тестом, расширением пакета B+ или сравнением производительности новых вариантов — они заблокированы по отсутствию документального подтверждения.

## Последующие эксперименты (ПОКА НЕ ВЫПОЛНЕНЫ)

1. Получить доказательные определения DID из соответствующего DME8FF_R PRG/A2L под данный SWFL (размер, endian, физический тип, единицы и смысл). Отдельно исследовать `4A37…4A3A` и справочные `5883…5888`.
2. На стоящем автомобиле записать сырые неизменённые ответы, проверив длину и структуру (RAW), затем сопоставить с OBD `01 0C/04/0B` и обычным B+ с учётом разнесения по времени. MAP: hPa/10 = kPa; относительная нагрузка не обязательно идентична OBD LOAD.
3. Только после внешнего утверждения списка разрешить одну контролируемую read-only транзакцию на отдельный DID; NRC/partial/timeout => запрет повтора, прежний BASELINE. Одно соединение, один запрос.
4. После подтверждения одиночных DID — экспериментальные группы; exact SID/DID/size/order, полный RAW, частота и валидность per-channel. Оценить p50/p95/p99 и объём набора, сравнить BASELINE / FAST_DID_TEST / FAST_BATCH_TEST.
5. На автомобиле сопоставить knock reference с RPM/MAP/IAT/углами/коррекциями, независимо подтвердить физическое значение и отдельно решить вопрос научной модели топлива.

**Результат текущей итерации:** программная защита, офлайн парсеры и пассивный сбор доказательств; **семантика не верифицирована**, 20–50 Гц и улучшение скорости не доказаны.

**Откат:** выбирать обычный BASELINE (все новые источники и так заблокированы) либо вернуть экспериментальную сборку Stage A #204 / PR #27. Не удалять пользовательские CSV и SharedPreferences. Ни один исходный формат CSV приложения не менялся.
