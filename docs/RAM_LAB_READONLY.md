# BMW OCTANE RAM LAB 1 — диагностическая тестовая сборка

## Назначение

Изолированная тестовая Android-сборка для подготовки к исследованию RAM Logging на конкретном DME.
**Это не RAM Logger и не Custom Patch.** Программа не проверяет поддержку UDS 0x23/0x2C и не читает произвольные адреса памяти.

## Безопасный эксперимент

- Отдельный applicationId: `com.example.bmwenettest.ramlab`; не заменяет установленный BMW OCTANE.
- Непосредственно перед тестом **остановить LOGGER** и выполнять тест только на стоянке.
- Меню **⋮ → RAM LAB • безопасная проверка DME → Начать**.
- Один TCP-сокет на время one-shot проверки; существующий DmeHistoryReader обеспечивает выбор ENET/VXSCAN, HSFZ-границы, тайм-аут и отмену.
- Только allowlist из UDS 0x22: F180, F181, F187, F189, 4A37, 4A49. VIN F190 не читается.
- Создаётся `bmw_ram_readiness_v1_<timestamp>.csv` в каталоге файлов RAM LAB. Фиксируются raw response, DID, время транзакции, статус, транспорт.
- После теста кнопка **Сохранить CSV** открывает системный выбор документа Android; можно сохранить отчёт в Downloads или другую доступную папку без ADB.
- При отрицательном ответе фиксируется NRC; при ошибке транспорта частичный CSV сохраняется.
- Любое появление ошибки связи требует остановить тест, не пытаться повторять агрессивные запросы.

## Чего не делает эта сборка

- Не посылает команды 0x23 (ReadMemoryByAddress), 0x2C (Dynamic DID), 0x10, 0x27, 0x2E, 0x3D, 0x31.
- Не переключает диагностические сессии и не меняет калибровки, память или прошивку.
- Не подтверждает достижимость 10/20/100 Гц и не оценивает октановое число.
- Не включает обоснование произвольного доступа к RAM по результату обычного чтения DID.

## Что проверить

1. Приложение установилось **отдельно** от обычного BMW OCTANE.
2. LOGGER STOP; на стоянке открывается меню RAM LAB.
3. Завершённый или частичный CSV создаётся без замены существующих записей.
4. Отказы/отсутствие поддержки DID явно видны в файле.
5. Оценивать успешность чтения по raw-ответам, а не только по сообщению UI.

## Критерий следующей итерации

После анализа идентификаторов ECU проверить совместимость RAM-протокола по достоверной документации/A2L и лабораторному стенду. Только затем проектировать отдельный экспериментальный механизм динамических DID.
