# BMW OCTANE 2.0 — согласованный интерфейс, реализация

**Версия:** ветка `experiment/bmw-octane-2.0`, PR #22. **Режим:** экспериментальная 2.0 APK; основное приложение 1.7 не меняется.

## Сценарий

Утверждённая последовательность: текущая заправка → запуск диагностики → подсказка следующего безопасного режима → реальные пригодные RPM×MAP наблюдения и прогресс → анализ с честной достоверностью → сравнение с 1.7.

Верх приложения: компактный логотип, заголовок и экспериментальная метка. Нижняя навигация всегда доступна, пять вкладок:

| Вкладка | Содержимое | Реальный источник |
| --- | --- | --- |
| Главная | текущая заправка, дата и АЗС; состояние DME; прогресс двух приоритетных STEADY; подсказка; крупные RPM/MAP; старт/стоп | `GuidedFuelTest` prefs, `SteadyTargets` persisted CSV & service snapshot, FAST broadcast |
| Заправки | создать топливный тест; субъективная оценка *только в диалоге создания*; текущая заправка и история | прежние prefs и `bmw_fuel_test_v1731_*.csv`; optional `octane2_refuel_rating_<id>` |
| Анализ | техническая достаточность STEADY/ACCEL, предварительный анализ; 1.7 ↔ 2.0 сравнительный отчёт/CSV | `GuidedFuelTest.Coverage`, `Octane2ComparisonReport`; неподтверждённого числового Fuel Score нет |
| Диагностика | источник RAM/OBD/DID, lambda, RPM/MAP, полный legacy Dashboard, температуры, топливные коррекции, соединение, ошибки | `ACTION_OCTANE2`, `ACTION_FAST_TELEMETRY`, `ACTION_STATUS` |
| Настройки | RAM/SWFL, DME B+/B/A, offline replay, прочие диагностические инструменты и экспорт | прежние обработчики, без дополнительного сокета |

Цвета совместимы с ранее согласованным тёмным дизайном: navy background, графитовые карточки, синий для информации/ожидания, зелёный только для подтверждённого покрытия/связи, янтарный для предупреждений. Вертикальные области прокручиваются, нижние вкладки закреплены, элементы помещаются на узких Android-экранах.

## Честный прогресс

Обе STEADY-цели требуют RPM `2500–2999` или `3000–3499` при абсолютном MAP `105–129` кПа. Индикаторы вычисляются **только из сохранённых валидных записей**, не из секунд работы LOGГER или мигающей визуализации. `SteadyTargets.Cell` требует 24 точки + 4 независимых сегмента + 2 запуска LOGGER. Сравнение количества валидных точек/сегментов/запусков проводится от канонической модели; чужое поле процента не является источником достоверности. После новой ручной заправки предыдущие STEADY-точки той же автомобильной сессии не засчитываются, но на диске остаются.

Подсказка выбирает недостающую область с наименьшим покрытием. Она не требует управления телефоном в движении и не предлагает разгона до опасной скорости, конкретной передачи или нарушения ПДД. Текущие RPM/MAP очищаются после потери свежих FAST событий; отсутствующие значения — «—», не 0.

Субъективная оценка, если задана при создании заправки, хранится отдельно по ID теста и не поступает в топливный алгоритм. Диагностика теперь запускается отдельным явным действием после выбора топлива, не автоматически во время создания заправки.

## Ограничения

- Исторические CSV, prefs `GuidedFuelTest` и `SteadyTargets`, интерфейсы `EnetLoggerService` и RAM-first fallback остаются совместимыми. Свои методы отображения не производят диагностических запросов.
- Достаточное покрытие **не равняется** валидированному относительному качеству топлива и тем более лабораторному RON. Главный числовой результат 2.0 закрыт статусом «Недостаточно данных».
- После пересоздания Activity выбранная вкладка восстанавливается, сохранённый прогресс подгружается с диска в отдельном executor, а не блокируя UI. После запуска соединения обновления получают из service broadcasts.
- При отсутствии ECU данных прогресс не растёт; на следующей аппаратной поездке необходимо проверить переходы CONNECTED/RECONNECTING/STOP, тайм-ауты, видимость UI в портретной/альбомной ориентации и отсутствие заметной деградации частоты DME.

Сборка/тесты проверяются GitHub Actions на PR #22. Результат автомобильного испытания **не подтверждён**.
