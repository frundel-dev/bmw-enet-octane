# BMW OCTANE 2.0 — экспериментальная диагностика RAM-first

**Статус:** экспериментальный Android APK, не калиброванный октанометр; отдельный package `com.example.bmwenettest.octane2`.
**База:** `feat/observation-replay-v1734` (v1.7.34, PR #13) и перенос **только проверенного** `RamMemoryProtocol` из `experiment/ram-lab-suite-v1`.
**Совместимость:** BMW OCTANE 1.7 остаётся отдельно установленным. Запрещено одновременное использование ENET обоими приложениями.

## Диагностика

- Единственный поток и один TCP reader `EnetLoggerService`, прежний read-only ENET/HSFZ/UDS/OBD и B+ → B → A fallback. Никакой `0x2C`, флешинга, RAM write, сканирования адресов.
- **Nkw RPM:** A2L `R4C9J797B_5d55-070_060_007`, SWFL `00005D55-070.060.007`, Bosch MG1CS201, RAM `0x60003B64`, `SWORD` little-endian, 1 rpm/count. Точный запрос `23 14 60 00 3B 64 02`; ожидается `63 LL HH`. Подтверждено отдельным RAM LAB, но на иной прошивке адрес недопустим.
- По умолчанию **RAM выключен**. В ⋮ → **BMW OCTANE 2.0 • RAM/SWFL** пользователь явно подтверждает совпадение своего A2L/SWFL. Перед первым чтением обязательны свежие OBD скорость **0 км/ч** и холостой ход **450–1800 rpm**; считанное RAM RPM сравнивается с OBD RPM. Если ECU отвергает запрос, RPM невалиден или получено большое расхождение, RAM отключается до нового старта LOGGER. Неопределённый ответ закрывает TCP с обычной процедурой reconnect; программа не пытается продолжать чтение несинхронизированного потока.
- Для **2.0 интерфейса** и нового сравнительного CSV после подтверждения используется RAM RPM; OBD остаётся резервом. **Fuel Score 1.7, исходная классификация STEADY и остальные исторические CSV продолжают использовать OBD RPM**. Данные из обоих последовательных чтений не синхронны, и их временное расхождение сохраняется. Новые RAM-адреса не добавлены. `Dzw_tot_kr` в работе оценки не участвует.
- **Фактическая λ:** после штатного чтения маски поддерживаемых OBD `01 20` выбирается `01 34` (wideband lambda/ток), иначе `01 24` (wideband lambda/напряжение), либо «недоступна». Только ответы точной длины 4 байта и с совпадающим PID. Опрос не чаще 4 с; возраст данных ограничен 8 с. `01 00` проверяет доступность `01 03` (состояние регулирования), опрос 5 с. Командное эквивалентное отношение `01 44` сохраняется **отдельно**: не является фактическим λ. STFT/LTFT — прежние данные 1.7.
- **PRG кандидат `STAT_LAMBDA_BANK1_WERT`:** пока не привязан к проверенному диагностическому заданию/распаковке и не опрашивается. При отсутствии валидной фактической λ поле пустое, а не 1.0 по умолчанию.
- Дополнительные OBD и RAM запросы увеличивают время диагностического цикла. Частота и влияние на DME должны быть измерены **на автомобиле** до признания 2.0 улучшением.

## UX и сравнение

Главный экран показывает текущую заправку через существующий сценарий **НОВАЯ ЗАПРАВКА**, статус DME, цветовой MAP/RPM, прогресс STEADY 2500–2999 / 3000–3499 при MAP 105–129 кПа. Крупная кнопка оценки осталась в диалоге заправки. Ручное взаимодействие с телефоном **во время движения не требуется**.

- `bmw_octane2_comparison_v1_<start>.csv`: отдельная строка на каждый FAST цикл: OBD RPM, RAM RPM, применённый для 2.0 RPM, статус RAM, задержки чтения, интервал, MAP/LOAD, свежесть actual λ, отдельно commanded mixture, STFT/LTFT, топливный контроль, legacy 1.7 score/confidence и прогресс целевого STEADY. Незаполненные поля обозначают **отсутствие подтверждённого измерения**, не ноль.
- `bmw_observations_v1_<start>.csv`: журнал каждого FAST цикла из 1.7.34; `bmw_steady_targets_v1732_*.csv`: история покрытия режимов. Существующие форматы остаются прежними.
- В ⋮ → **BMW OCTANE 2.0 • экспорт сравнения** можно сохранять CSV через Android Storage Access Framework. В ⋮ → **Offline replay • наблюдения** можно переиграть архив без DME.
- 1.7 и 2.0 применяют прежнюю наблюдательную модель к одному OBD потоку; 2.0 RAM stream выведен отдельно до валидации. Значение legacy score сохраняется как **контроль**, но главный экран 2.0 не показывает его как доказанное качество. Новая модель 2.0 ещё не обучена и сообщает **«Недостаточно данных»**.

## Тестирование и ограничения

GitHub Actions для этого PR: `:app:testDebugUnitTest`, `:app:lintDebug`, `:app:assembleDebug`. JUnit: перенос RAM LAB, проверка gating RAM, NRC/framing, границы OBD PID 0x24/0x34/0x03 и разделение фактической/заданной смеси, CSV, регрессии HSFZ, legacy Fuel Score.

**Не проверено без автомобиля:** работоспособность RAM во время динамической нагрузки, точность последовательной регистрации, реальная поддержка 0x24/0x34, влияние дополнительных запросов на частоту/отказы, достаточность выборки, качество топлива, повторяемость между заправками. Данный APK не предоставляет лабораторный RON/MON.
